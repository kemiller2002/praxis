1. Item and acceptance criteria
-------------------------------

Obligation: framework/standards/IDENTIFIERS.md:14 lists CN and GL among the
identifier prefixes, but the F# artifact model (src/Ros.Domain/Artifacts/
Model.fs:44-55 ArtifactKind, :66-120 ArtifactKinds.configurations) defines no
such kinds, so CN/GL records are never enumerated by the loader, never
projected into a registry and never validated. Direction: add the kinds.

Acceptance criteria (verbatim intent, numbered as in the description):

  AC1  CN and GL are artifact kinds with a documented root directory, allowed
       statuses and identifier/filename rules consistent with the standards.
  AC2  `praxis registry build` generates their registries and
       `praxis registry check` detects staleness.
  AC3  `praxis validate` applies to them the same identifier, filename,
       status, reference and provenance checks as other kinds.
  AC4  The starter scaffolds and the Python artifact-validator oracle
       (tools/ros_cli.py) agree with the F# model wherever they enumerate
       kinds.
  AC5  Tests; afterwards the standards and the tooling no longer disagree.

Depends on: nothing. No other backlog item is touched.

3. Design
---------

Invariants and shared infrastructure
  - ArtifactKinds.configurations is the single source of truth. Loader,
    projection, registry transaction allow-list, stale check and build all
    derive from it, so adding two entries makes CN/GL discovered, registered,
    checked and transactionally written with no pipeline change.
  - Validation is generic per document; the only per-kind data in policy is
    the status table. Identifier regex already contains CN|GL.
  - Provenance is generic over loaded documents.
  - Registry bytes for the existing eight kinds must not change (frozen
    fixture hashes, ArtifactTests "frozen valid fixture ...").

Contracts
  - Concept:   prefix CN, name "concepts", SourceDirectory
               "research/concepts", RegistryPath "registries/concepts.json",
               OptionalRegistry = true.
  - Glossary:  prefix GL, name "glossary", SourceDirectory
               "research/glossary", RegistryPath "registries/glossary.json",
               OptionalRegistry = true.
  - Statuses (both): draft, review, accepted, superseded, withdrawn — the
    canonical research-artifact lifecycle (ARTIFACT-LIFECYCLE.md); DF/EV use
    the same set.
  - Identifier: <CN|GL>-<AREA>-<YYYY>-<TOKEN> (IDENTIFIERS.md), filename
    <ID>--<short-kebab-title>.md; no legacy filename exception (the legacy
    rule is research-package only, README.md:100).

Why optional registries: existing installations have no CN/GL registry file;
making the registries mandatory would make every installed repository's
`registry check` / `validate` report two stale registries on upgrade. This is
exactly the RQ rationale (Model.fs:58-61).

Validation rules: unchanged code; new status entries only.

Error model: unchanged (ArtifactFinding path/field/message; stale message
"registry is stale; run 'praxis registry build'").

Transaction boundaries: unchanged; registry writes for CN/GL go through the
existing RegistryWriteLease and RegistryTransaction, whose allow-list is
derived from configurations.

Python oracle (tools/ros_cli.py), kept dependency-free:
  - ID_RE gains RQ (and keeps CN, GL) so its prefix set equals the F# one.
  - ALLOWED_STATUS gains RQ, CN, GL with the F# sets.
  - KIND_CONFIG gains requirements, concepts, glossary, each with an
    optional flag; rendered registries are skipped for an optional kind
    with no artifacts and no existing file (mirrors Operations.fs:67-91).
  - Written as pure functions/comprehensions.

Documentation:
  - framework/standards/IDENTIFIERS.md: kind table (prefix, kind, root
    directory, registry, lifecycle) including CN and GL; minor version bump.
  - framework/protocols/ARTIFACT-LIFECYCLE.md: name CN and GL as research
    artifacts under the research lifecycle; minor version bump.
  - docs/features/artifact-management/manifest.md: optional registries list.


4. Compatibility
----------------

  - Existing repositories: no CN/GL files -> no registries required, no new
    findings. Repositories that already keep CN-/GL- records under
    research/concepts or research/glossary will now have them validated and
    registered; findings there are the intended effect.
  - A CN/GL record kept in another directory is still not discovered (same
    as any kind outside its source directory); documented.
  - Frozen fixtures and golden registry bytes unchanged.
  - Starter and install goldens unchanged.
  - Python oracle output for existing kinds unchanged; it newly registers RQ
    (previously ignored), aligning it with F#.


5. Tests
--------

F# (tests/Ros.Tests/ArtifactTests.fs):
  - configurations contain CN -> research/concepts, registries/concepts.json
    and GL -> research/glossary, registries/glossary.json, optional.
  - a temporary repository with valid CN and GL records: validate clean,
    registry build writes concepts.json and glossary.json containing them,
    second build idempotent, tampering makes registry check report stale.
  - an empty repository: no CN/GL registry is written or required.
  - CN/GL records get identifier, filename, status, duplicate, broken
    reference and reciprocal-supersession findings.
  - provenance: a new CN record after the policy date without provenance is
    reported (ProvenancePolicy through the loaded document set).
  - starter agreement: starter registries equal the non-optional kinds'
    registry files; every scaffolded research/<dir>/.gitkeep is a kind
    source directory.
Python (tests/test_ros_cli.py):
  - oracle KIND_CONFIG/ALLOWED_STATUS/ID_RE prefixes agree with the F#
    configurations parsed from Model.fs/Policy.fs.
  - CN/GL valid set builds registries and passes; status violation reported;
    optional registries absent for empty kinds.
Full suites: dotnet Ros.Tests, python unittest; ./praxis registry check and
./praxis validate on this repository.


6. Risks
--------

  - Directory naming ("glossary" singular vs plural kinds): chosen to match
    the existing uncountable "evidence"; the standards did not name
    directories, so this analysis and IDENTIFIERS.md now do.
  - Status set choice is a policy decision the standards only imply via the
    research lifecycle; documented in the lifecycle protocol.
  - The Python oracle's legacy research-package filename rule and ID_RE do
    not accept the 3-digit RP/REP legacy form F# accepts (Policy.fs:10-17);
    that is not a kind enumeration and is out of scope; noted, not changed.
  - schemas/artifact-metadata.schema.json prefix pattern lacks RQ (CN/GL are
    present); out of this item's CN/GL scope, noted.
  - Telemetry/provenance code paths keyed by prefix (ProvenancePolicy
    requireOriginator) are unaffected; CN/GL get warning-level originator
    findings like other non-RQ kinds.
