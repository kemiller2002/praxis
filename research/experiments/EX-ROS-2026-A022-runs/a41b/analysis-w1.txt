- Item: ACTOR-KIND-ANCHOR ("ActorKind extension pattern accepts a trailing
  newline ($ anchor)"), `./praxis work show ACTOR-KIND-ANCHOR`
- Execution repository: kemiller2002/praxis, branch experiment/a022-run-a41b
- Base commit: f806f817e4656e00550313d839b59ceea87a682d

1. Item and acceptance criteria
-------------------------------

Obligation: ActorKind.tryParse (src/Ros.Domain/Provenance/Actor.fs:21-38)
validates an extension kind with `^x-[a-z0-9][a-z0-9-]*$`. In .NET, `$`
without RegexOptions.Multiline also matches immediately before a final
"\n", so `x-agent\n` is accepted and stored verbatim as
ActorKind.Extension "x-agent\n". Fix by anchoring with `\z`, and audit
the other Domain patterns for the same defect.

Acceptance criteria (verbatim from the backlog description):
  AC1. ActorKind.tryParse rejects a value with a trailing newline or
       carriage return (for example x-agent followed by a newline).
  AC2. Every regular expression under src/Ros.Domain used to validate a
       whole value is audited; each one that anchors with $ is corrected
       (for example to \z) or recorded with the reason it is safe; the
       audit list is part of the completion evidence.
  AC3. A test for each corrected pattern.
  AC4. No accepted valid value changes.
Also stated: not to be merged to main before experiment EX-ROS-2026-A022
is evaluated and the repository owner decides. No PR or merge is part of
this item.

Note on "carriage return": `$` never matched before a bare "\r", so
`x-agent\r` and `x-agent\r\n` were already rejected (`\r` is not in the
character class); only a single trailing "\n" slipped through. The test
still covers "\n", "\r" and "\r\n" so AC1 is demonstrated, not inferred.

No new abstraction is introduced. A shared "whole-value regex" helper was
considered (e.g. a `Pattern.whole` that appends `\z`) and rejected: the
patterns live in five namespaces with a strict compile order
(Telemetry before Provenance, etc.), the newer code already writes `\z`
inline, and a helper would be a larger, cross-cutting change for no
behavioural gain.

3d. Design
 - Contract: each predicate/parser keeps its signature and result type;
   only the end anchor changes from `$` to `\z`. For P18 the generated
   pattern becomes `^...\z`.
 - Validation rule: a whole value matches only if the pattern consumes
   every character; `\z` is end-of-input with no newline exception.
 - Error model: unchanged. Rejected values flow into the existing
   findings/None/Error paths (e.g. "unknown actor kind", InvalidWorkItemId,
   "execution identity must be portable ..."). The ImplementationLanguage
   and Telemetry messages quote the pattern text; the EXE message at
   TelemetryValidation.fs:536 quotes `^EXE-[A-Za-z0-9._-]+$` and is left
   as is (it is a human-readable description, pinned by existing golden
   behaviour; changing it is not required by any criterion).
 - Stores / transaction boundaries: none touched. No stored format
   changes; values on disk that are valid today stay valid (AC4).


4. Invariants and shared infrastructure
---------------------------------------

 - Invariant: for every string s without a trailing "\n", `^R$` and `^R\z`
   decide identically (RegexOptions.Multiline is not used by any audited
   pattern; verified in the grep above). Therefore AC4 holds by
   construction; tests additionally assert each previously-accepted
   example is still accepted.
 - WorkItemId.isValid (P13) is shared by Backlog, QueueValidation,
   Checkpoint, Reconciliation, WorkGroups, ContextPlan and CLI argument
   parsing (src/Ros.Cli/CheckpointCommands.fs:340, 815;
   ReconciliationCommands.fs:76). Fixing it once tightens all of them.
 - The Telemetry and Provenance EXE- patterns (P3, P11) are separate
   copies because of compile order; both are fixed so they stay
   consistent with RequestValidation.executionIdPattern (already `\z`).
 - Original Node implementations (TelemetryValidation.fs docs refer to
   tools/ros_telemetry.mjs, PathFilter "mirrors Node") used JavaScript
   `$`, which (without the m flag) matches only at end of input. `\z` is
   the faithful .NET equivalent, so this restores parity rather than
   changing semantics.


5. Compatibility
----------------

 - Only inputs ending in "\n" change outcome (accepted -> rejected). Such
   values cannot be produced by the CLI's own writers (they emit the
   parsed, already-validated values) and would be corrupt if present.
 - PathFilter (P18): a path ending in "\n" no longer matches an ignore
   glob, so it would count as meaningful. This is the conservative
   direction for attribution (nothing is silently ignored).
 - `./praxis validate` is run on this repository after the change to
   confirm no stored record is newly rejected.
 - Out of scope (AC2 names src/Ros.Domain only): a few `$`-anchored
   patterns exist in other projects (`grep` finds 6 candidate lines
   outside Ros.Domain). They are not changed here; if any validates a
   whole value it should be filed as its own backlog item.

7. Risks
--------

 - Missing a pattern: mitigated by the grep over every Regex/IsMatch use
   in src/Ros.Domain and the explicit 3a/3b/3c lists.
 - A stored record that today relies on a trailing newline: mitigated by
   running `./praxis validate` on this repository; any finding would be
   reported, not hidden.
 - Error-message drift: messages are unchanged, so golden CLI tests are not
   expected to move.
 - Generated pattern in PathFilter: the `\z` is appended in an
   interpolated string; tested directly through globMatch.
