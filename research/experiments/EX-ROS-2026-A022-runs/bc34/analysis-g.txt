1. Members
----------

  Obligation: anchor whole-value validators so "x-agent\n" is rejected; audit Domain.
  Criteria: (1) ActorKind.tryParse rejects trailing LF / CR; (2) every whole-value
  regex under src/Ros.Domain audited, each `$` anchor corrected (\z) or recorded
  as safe with reason, audit list is completion evidence; (3) a test per
  corrected pattern; (4) no accepted valid value changes.
  Depends on: -

ATTR-RECONCILE-SYMLINK-SUBMODULE (low) - content-match symlinks and submodules.
  Criteria: (1) reconciled symlink with unchanged target matches its recorded
  blob (what Git stores for the link, not the followed file); (2) reconciled
  submodule matches while its gitlink commit is unchanged; (3) a changed link
  target or gitlink still fails closed; (4) regular-file behaviour unchanged;
  (5) tests use real Git fixtures for both cases.
  Depends on: -

PRAXIS-CN-GL-KINDS (medium) - govern CN (concept) and GL (glossary) kinds.
  Criteria: (1) CN and GL are artifact kinds with documented root directory,
  allowed statuses, identifier/filename rules consistent with the standards;
  (2) registry build generates their registries and registry check detects
  staleness; (3) validate applies identifier, filename, status, reference and
  provenance checks to them; (4) starter scaffolds and tools/ros_cli.py agree
  with the F# model wherever they enumerate kinds; (5) tests; standards and
  tooling no longer disagree.
  Depends on: -

PRAXIS-PLAN-ERROR-HISTORY (medium) - persist planner estimate error over time.
  Criteria: (1) explicit opt-in planner command records a replay's
  estimate-error summary durably, keyed by planner version, repository commit
  and as-of time, idempotent for identical inputs; all other plan commands stay
  read-only; (2) read view reports error over time, segmented by task class and
  (where recorded) provider/model/runtime, no hard-coded provider claims;
  (3) measurements older than a configured horizon are reported stale and not
  authoritative; (4) deterministic output (PRX-PLAN-002); (5) praxis validate
  checks the stored history; (6) tests and docs/planning.md status row.
  Depends on: - (its store layout is chosen together with PRAXIS-STATE-MERGE-01)

PRAXIS-STATE-MERGE-01 (high) - parallel work conflicts in single-document state.
  Criteria: (1) supported, documented path merges two branches whose Praxis
  state changed independently, no hand edit of .ros; (2) append-only events kept
  exactly once in deterministic order, id-keyed items merged three-way;
  (3) genuinely conflicting changes to one item fail closed naming the item;
  (4) praxis validate passes on the merged result in a test reproducing the
  conflict pattern; (5) every single-document state file that ordinary parallel
  work modifies is covered or listed as not covered with reason;
  (6) docs/work-protocol.md documents the path; tests.
  Depends on: -

New abstractions proposed and what was considered:
- A pure three-way merge module for Praxis state (Domain). Considered: the
  recovery journal (.ros/transactions) - it recovers one writer's interrupted
  transaction and has no notion of two histories; nothing else merges.
  `grep -rn "merge" src/Ros.Domain` finds only planner/grouping text.
- A planner error-history store. Considered: telemetry executions (per
  execution, not per replay), work groups store (different domain). None fits.


3. Cohort-level design
----------------------

Common architecture and shared invariants
- Whole-value validation in Domain anchors with \z (ACTOR-KIND-ANCHOR). Every
  new validator introduced by the other items (merge driver path kinds, history
  record IDs/fields) follows the same rule, so the audit stays true afterwards.
- State that ordinary parallel work writes must be mergeable without hand edits
  (STATE-MERGE). PLAN-ERROR-HISTORY adds a new .ros store; it is designed as an
  append-only JSONL file whose lines carry a content-derived id, so the same
  append-only union rule that merges events.jsonl merges it. This is the one
  genuine shared design point in the cohort.
- validate is the single composition point (computeUnifiedFindings): CN/GL
  ride the existing artifact pipeline; history findings are a new contributor.

Conflicting requirements and resolution
- STATE-MERGE "never silently pick a side" vs. derived bookkeeping fields
  (current.json updatedAt/actor, queue.json nextSeq). Resolution: these are
  documented derived fields with a deterministic rule (latest timestamp, max
  sequence, actor of the latest update), not items; every id-keyed item and
  every other field merges three-way and fails closed on divergence.
- PLAN-ERROR-HISTORY "all other plan commands stay read-only" vs. a writing
  command. Resolution: only the new `plan record-error` writes; the existing
  read-only test continues to hash state around every other command.
- Idempotency vs. a recording timestamp: the record carries no wall-clock
  field; its key is (planner version, commit, as-of) and its id is a SHA-256 of
  the canonical record, so re-recording identical inputs is a no-op.
- Planner `praxisStateMergeSafe` default stays false: installing the driver is
  a repository's explicit choice; docs say to set the flag once installed.

One design serving several items
- Append-only JSONL union with id keys: events.jsonl (STATE-MERGE) and the
  estimate-error history (PLAN-ERROR-HISTORY).
- \z rule: ACTOR-KIND-ANCHOR's audit plus new validators of the others.
- Nothing is shared between ATTR (Git path hashing) and CN/GL (artifact kinds)
  and the rest beyond test helpers: they are solved separately; no shared
  abstraction is invented for them.

Compatibility
- \z changes reject only values ending in a newline; no valid value changes.
- CN/GL registries are OptionalRegistry=true so existing installations do not
  become stale on upgrade (RQ precedent).
- ATTR changes only paths that are symlinks or submodules; regular files keep
  `git hash-object`.
- Merge driver is opt-in via `praxis state merge install` (.gitattributes +
  local git config); without it Git behaves as today.
- History store absent = no findings, no behaviour change.

Common tests
- Table-driven anchor tests; real Git fixtures (temp repos) for ATTR and
  STATE-MERGE; F#/Python oracle parity for kind enumeration; determinism
  (render twice, byte-compare) for the history read view.

Risks of solving each item separately
- A history store designed without the merge rule would be a new conflicting
  single-document file (exactly the STATE-MERGE failure).
- New validators written after the anchor audit could reintroduce `$`.
- Otherwise low: the items touch disjoint modules.

Shared infrastructure attribution
- Merge engine: PRAXIS-STATE-MERGE-01. History store's mergeability:
  PRAXIS-PLAN-ERROR-HISTORY (uses the engine's JSONL rule; commit names both).
