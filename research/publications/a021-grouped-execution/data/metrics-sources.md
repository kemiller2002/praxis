# Metrics provenance, conflicts and gaps

> **INTERNAL.** This file names platform session identifiers. They must not
> reach an anonymous artifact. Strip this file and the `internal_ref`
> field/column of `metrics.json` / `metrics.csv` before release.

Generated data: `metrics.json` and `metrics.csv` (long format, one row per
study x arm x unit x metric), written by `scripts/extract_metrics.py`.
Checked by `scripts/verify_metrics.py` against the records' reported figures.
Known discrepancies are in `metric-conflicts.json`. Tables and prose macros
are generated by `scripts/build_tables.py` into `manuscript/tables/`.

```
python3 scripts/extract_metrics.py      # regenerate data/metrics.{json,csv}
python3 scripts/verify_metrics.py       # byte-identity + record checks; exit 1 on unexplained mismatch
python3 scripts/build_tables.py         # regenerate manuscript/tables/*.tex
python3 scripts/build_tables.py --check # exit 1 if the committed tables are stale
```

## 2. Definitions and inclusion rules

- **Arms.** `grouped`; `independent` (the protocol's "control").
- **Session roles.** `implementation` (worked an item and completed it),
  `failed_attempt` (A021 item-04 attempts 1 and 2), `orchestration` (R2
  independent arm's own orchestrator C), `evaluator` (A021 evaluator; arm `none`).
- **`agg:workers`** = implementation + failed_attempt sessions of the arm. It
  excludes orchestrators and evaluators. **This is the A021-comparable
  definition.** A021 independent = 7 sessions; R2 independent = C1..C5.
- **`agg:workers+orchestration`** adds the arm's own orchestration sessions.
  It is defined for platform usage and wall-clock spans only. R2 independent
  adds C; R2 grouped has none, so it equals agg:workers. For A021 it is
  `unknown`: one orchestrator served both arms and the evaluator, and its usage
  is not in the experiment's sources.
- **`agg:arm`** = an arm-level figure with no session breakdown (Git, evaluations).
- Sums run over sessions with a value. If any included session lacks one, the
  aggregate is `lower_bound`. Context uses the max, not a sum.
- **Time definitions.** `session_span` = platform `created_at` to the session's
  end. A021 `finishedAt` equals get_session `updated_at` (confirmed by live
  lookup for the grouped session and others). R2 End = `updated_at` after
  idle. A blocked session ends at `blockedAt`. `active_session_sum` = sum of
  spans. `wall_clock_span` = first start to last end of the included sessions.
  `blocked` = `blockedAt` to `abandonedAt`. `transcript_span` =
  session_metrics.py's first-to-last transcript entry (ends before the final
  steps).
- **Derived values** (`derived` section): ratio = independent/grouped;
  reduction = (independent - grouped)/independent. They are computed only from
  the two aggregate rows of the same metric and unit. `completeness` is
  `partial` when either operand is not complete. `comparable_to_other_study`
  is false where the definition differs from the other study's.

## 4. Conflicts found and their resolution

These are summarized here; `metric-conflicts.json` holds the machine-checked form.

**CF-01: A021 tokens, platform versus transcript.** EV-A064's 112,377 vs
244,630 output and 24.5 M vs 45.1 M cache-read are sums of `sessions.json`
`platformUsage` over all A021 independent sessions (7, including both failed
item-04 attempts). EV-A070's and POST-UNBLINDING's 110,627 vs 176,304 output
and 23,872,205 vs 32,211,852 cache-read are sums of the session_metrics.py
files (grouped.json at `5face88`; control-01..05.json at `8ea9be2`). Those
files exclude attempts 1-2 (no file exists), cover only attempt 3 for item 04
(`metricsNote` in sessions.json), and were all written before each session's
final checkpoint. Both reproduce exactly. The script independent total is a
lower bound: 176,304 is 72% of the platform figure, and the grouped script
total is 98% of its platform figure. The same applies to EV-A070's 114/237
requests, 52/134 reads, 53/159 searches, 16/34 builds and POST's 13/15 test
runs: they reproduce, but EV-A070/POST drop EV-A064's "at least". Resolution:
platform usage for A021 resources; transcript counts only where the platform
has none, marked lower_bound.

**CF-02: "platform cost was unavailable" (POST-UNBLINDING-METRICS) is
incorrect.** `sessions.json` has carried get_session `cost_usd` for every A021
session since the run (pinned `bc5a8d8`; EV-A064 and the protocol Results
quote $9.48 / $21.51). What was unavailable was Praxis `cost.*` telemetry and
the planner's cost prediction. The R2 evaluator appears to have read only the
transcript files, whose `costUsd` is null.

**CF-03: A021 independent active time is 111 min 22 s, not 112 min.** Spans
from sessions.json: 845 + 1,305 + 893 + 615 + 769 (attempt 2 to blockedAt) +
445 + 1,810 = 6,682 s. EV-A064 and the protocol say 112 min. The record does
not explain the extra minute. The figure is clearly a sum that ends attempt 2
at the block; ending it at abandonment would give 238.5 min.

**CF-04: "Peak context" is end-of-session context.** `context_used_tokens` is
get_session `context_usage.used_tokens` when recorded. It approximates the
peak only because there were no compactions.

**CF-05: R2 independent cost/tokens include the control orchestrator.** Yes:
$26.0492768 = C $3.4929240 + C1..C5 $22.5563528. Likewise input 956 (C 138),
output 262,893 (C 26,239), cache-read 62,960,709 (C 8,472,440) and cache-write
1,074,120 (C 159,138). The grouped arm had no arm orchestrator. A021 excludes
its shared orchestrator from both arms. The A021-comparable R2 cost reduction
is **52.33%** (ratio 2.10), not 58.72%. 58.72% is reproducible but defined
differently.

**CF-06: R2 "elapsed" is a wall-clock span, not a sum.** 2h23m35s = 8,615 s
runs from the run record's common arm start 15:22:55Z (the grouped session's
created_at) to the control orchestrator's last update 17:46:30Z. The
orchestrator's own created_at is 15:22:57Z, giving 8,613 s and a 61.07%
reduction. The span includes the gaps between workers (12 m 42 s, 9 m 50 s,
2 m 15 s, 7 m 56 s), the 31 s before C1, and the 9 m 46 s after C5. Sum of
worker sessions: 6,033 s (100 m 33 s), 44.42% reduction. Worker span: 7,996 s,
58.07%. The grouped arm's 55m53s is both its span and its active time. So
61.08% compares with A021's wall-clock span reduction (79.05%, which includes
a 2 h 7 min permission block), not with A021 "active session time" (45.06%).
The two "active" reductions (45.06% vs 44.42%) are the closest like-for-like
pair.

exactly (cost, all token fields and, for A021, context). Two A021 sessions

**CF-09: R2 worker metrics schemas differ** (run record deviation C4).
Extraction takes only the script's own values (`R2_SCRIPT_OVERRIDES` in
extract_metrics.py):

  testRuns are session-corrected: C5 builds 6 vs script 8, testRuns 3 vs 2.
- control-03 reports only a corrected builds value (4), so its script build
  count is null.
- control-03's tokens exclude one Explore subagent (138,787 untyped tokens),
  recorded as `subagent_tokens_untyped_transcript`.
