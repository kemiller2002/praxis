The problem

An agent says the work is done. Now answer the questions.

  1. Which requirement was this for?
  2. Who, or what, did the work?
  3. Which provider, runtime and model?
  4. What changed, and why?
  5. Which tests ran?
  6. Where is the evidence?
  7. What did it cost?
  8. When the work changed hands, where did one agent stop and the next begin?

A commit message is not an answer. A green check is not an answer. “Done” is not an answer.

What is Praxis

Agents can write code. Praxis makes their work accountable.

Praxis is a repository-native work protocol. Work is captured, started, blocked, resumed and completed through one command-line interface, and every step is recorded next to the code it produced: which agent did it, in which execution, against which commits, with which evidence.

How it works

From intent, to execution, to evidence.

Every link in the chain is a record in the repository. Each one points to the next, so a finished piece of work can be followed back to why it started.

  1. Requirement

    The intent. An issue, a requirement record, a decision. Praxis records where work came from as its source reference.

    work capture --source-reference

  2. Work item

    A unit of work with a lifecycle: captured, ready, active, blocked, complete. The protocol refuses illegal transitions.

    work capture · work start

  3. Execution

    One bounded attempt at the work by one actor. Identity, start, end and repository baseline are recorded when it opens.

    EXE-…

  4. Steps

    Starting, blocking, resuming and completing are events, appended to a log in the repository with the actor that performed them.

    work block · work resume

  5. Changes

    Commits made during the execution are measured against its clean baseline: files, lines, tests touched.

    git

  6. Tests

    Test evidence is required to complete. A work item without it stays open.

    --evidence tests=…

  7. Evidence

    Completion names the files that prove the claim. The execution is then finalized and its record closed.

    work complete

  8. Reconciliation

    A commit made outside any work item is not silently absorbed. It is attributed explicitly, with a reason, or it stays unresolved.

    work reconcile

  9. Verified history

    Repository validation checks the records against each other and against Git.

    validate

Anatomy of an execution record

This is what one execution looks like when every source reports. The values are an example of layout, not a measurement: nothing in it came from a real run, and it is labelled so.

Every value carries its quality. Observed came from the runtime. Derived was calculated by Praxis from other records. Estimated is labelled as such, with its source. A value no source supplied is unknown or unavailable, never zero.

Git and Praxis

Git knows what. Praxis knows why.

Git is the record of change, and Praxis depends on it. Praxis keeps its own records in the same repository, in files Git versions like any other, and adds the context a diff was never meant to carry.

What Git establishes and what Praxis adds
Question Git establishes Praxis adds
What changed The exact content of every change, line by line. Summarizes the changes each execution made, measured from its own clean baseline.
Who The configured author and committer of each commit. The actor behind the work: kind, provider, runtime, and model when it is reliably known.
Why The commit message, as written. The work item the change belongs to and the source it came from.
When Author and commit timestamps. When the work started, blocked, resumed and completed, and how long each execution ran.
Proof The history itself. The implementation and test evidence named at completion.
Handoffs Commits in sequence. Where one execution ended and the next began, and who ran each.

Agents

No anonymous work.

Agents, people and automation work under the same protocol. Each execution records who ran it, and how Praxis knows.

Identity

Actor kind, provider and runtime are detected from the runtime environment for OpenAI Codex, Claude Code, Gemini CLI, GitHub Copilot and GitHub Actions. They can also be declared explicitly. The record keeps the mechanism, so a declaration is never mistaken for a detection.

Model

Recorded when the runtime reports it or it is declared. Otherwise it is recorded as unknown. Praxis does not infer a model from a provider.

Execution boundaries

Every attempt at a work item is its own execution with a start, an end and a repository baseline. When work changes hands, the next actor opens a new execution that points to its parent.

Telemetry, when it exists

Tokens, cost and runtime measurements are recorded when a runtime stream, hook or OpenTelemetry exporter supplies them. Cost is taken from the runtime or calculated from a named price source; it is never guessed.

Every value says how it is known

Observed
Reported by the runtime or its telemetry.
Derived
Calculated by Praxis from other records, such as wall time from timestamps.
Declared
Stated explicitly by the actor or its configuration, and recorded as a declaration.
Unknown
No source could say. Recorded as unknown.
Unavailable
The runtime can report it, but nothing was supplied for this execution.

A missing value is never filled with a zero.
