You said it's done. Prove it.

The problem

An agent says the work is done. Now answer the questions.

  1. Which requirement was this for?
  2. Who, or what, did the work?
  3. Which provider, runtime and model?
  4. What changed, and why?
  5. Which tests ran?
  6. Where is the evidence?
  7. What did it cost?
  8. When the work changed hands, where did one agent stop and the next begin?

A commit message is not an answer. A green check is not an answer. “Done” is not an answer.

What is Praxis

Agents can write code. Praxis makes their work accountable.

Praxis is a repository-native work protocol. Work is captured, started, blocked, resumed and completed through one command-line interface, and every step is recorded next to the code it produced: which agent did it, in which execution, against which commits, with which evidence.

How it works

From intent, to execution, to evidence.

Every link in the chain is a record in the repository. Each one points to the next, so a finished piece of work can be followed back to why it started.

  1. Requirement

    The intent. An issue, a requirement record, a decision. Praxis records where work came from as its source reference.

    work capture --source-reference

  2. Work item

    A unit of work with a lifecycle: captured, ready, active, blocked, complete. The protocol refuses illegal transitions.

    work capture · work start

  3. Execution

    One bounded attempt at the work by one actor. Identity, start, end and repository baseline are recorded when it opens.

    EXE-…

  4. Steps

    Starting, blocking, resuming and completing are events, appended to a log in the repository with the actor that performed them.

    work block · work resume

  5. Changes

    Commits made during the execution are measured against its clean baseline: files, lines, tests touched.

    git

  6. Tests

    Test evidence is required to complete. A work item without it stays open.

    --evidence tests=…

  7. Evidence

    Completion names the files that prove the claim. The execution is then finalized and its record closed.

    work complete

  8. Reconciliation

    A commit made outside any work item is not silently absorbed. It is attributed explicitly, with a reason, or it stays unresolved.

    work reconcile

  9. Verified history

    Repository validation checks the records against each other and against Git.

    validate
