# Praxis shared application foundation requirements

Status: **Required**

These requirements apply to Praxis runtime and UI surfaces (including its `ros` compatibility aliases) when the named capability is applicable. The URL-addressable state section is also the portfolio-wide standard for every Echelon web application.

## Aegis

1. Praxis's native .NET/F# CLI, infrastructure, repository, filesystem, process, package, network, Git, and other external operational boundaries MUST use Aegis for unexpected operational failure.
2. Expected Praxis outcomes such as invalid work transitions, verification failures, stale installation state, user-owned-file conflicts, unsupported commands, and policy refusals MUST remain typed Praxis/Ordo outcomes and MUST NOT be converted into Aegis faults.
3. Praxis has no JavaScript edges (RQ-ROS-2026-A024); every launcher, server and hub boundary is F#/.NET or a thin shell launcher. Launchers MUST NOT invent a competing durable fault taxonomy: they MUST return explicit non-success diagnostics and preserve enough context for the native boundary to classify the fault without exposing secrets.
4. Retry/recovery MUST respect idempotency and unknown-effect state, especially around repository mutation, package installation, Git operations, and agent/provider invocation.
5. Aegis context MUST redact credentials, tokens, private repository data, and sensitive work content.
6. Native Aegis dependencies MUST be pinned to released versions and tested with replaceable sinks.

## Forma

1. Praxis web and hub interfaces MUST consume a pinned Forma release.
2. Existing Forma patterns/components/tokens MUST be used before Praxis-local presentation equivalents.
3. Forma CSS or component markup MUST NOT be copied/forked into Praxis merely for convenience.
4. Native HTML remains the semantic authority; Forma owns presentation; Praxis owns work state, legal transitions, permissions, evidence, and repository meaning.
5. Mobile, keyboard, focus, accessibility, non-color-state, and responsive behavior inherit Forma's shared contracts.
6. Operational-fault presentation in interactive UI SHOULD use Forma's standard fault/error presentation components.

## Folio

1. Folio is conditional until Praxis exposes printable/PDF/paginated work reports, execution summaries, telemetry reports, evidence packets, audit reports, or similar document surfaces.
2. Once such a surface exists it MUST consume a pinned Folio release and use existing Folio primitives before local print implementations.
3. Forma remains responsible for interactive controls around document preview; Folio owns printable document intent; Praxis owns the document's work/evidence meaning.

## URL-addressable state (deep linking)

This section is a portfolio-wide standard. It applies to **every Echelon web application**, existing and future, and to Praxis's own web and hub interfaces. Every new application's requirements include it, and Conditor's web-application templates carry it. Praxis owns the text and verifies the parts a repository can show with `praxis foundations verify` (the `routing` capability, `ECHELON-FND-ROUTING-NNN`; see [`docs/application-foundations.md`](../docs/application-foundations.md)). Limen 0.9.0 implements it as its routing / URL-state module (Limen LCP-088..112, `DF-LIMEN-2026-0006`): `@echelon-foundry/limen/routing` and the F# package `EchelonFoundry.Limen.Routing` (namespace `Limen.Routing`).

**Navigable state** is the screen or route, the entity IDs it shows, and the view parameters that select what it shows: the selected date or period, filters, sort, search, tab and page. A person who copies the URL and pastes it into another browser opens the same view.

1. **SAF-URL-1 The URL is the source of truth for navigable state.** The application derives the view from the URL and writes the URL when that state changes. It never holds navigable state only in memory or storage. A cold load of a copied URL reproduces the view. When sign-in is required, the application captures the target before authentication and resumes it afterwards (Limen `ReturnTo.capture`/`resume`, `captureReturnTo`/`resumeReturnTo`). A return target never leaves the application. The view then matches what the sender saw, subject to the recipient's permissions. *Test:* for each inventory route, open its URL in a fresh browser context. After any sign-in, the same view is shown with the same parameters applied.
2. **SAF-URL-2 Entity IDs and view parameters are in the path or the query, in one canonical form.** Entity IDs are path parameters, and view parameters are query parameters. Each is typed `string`, `int`, `bool`, `date` (`YYYY-MM-DD`), `month` (`YYYY-MM`, for a period), `enum` or `set`. The canonical URL contains declared parameters only, parent first, in declaration order. It omits any parameter equal to its default. It writes a set's members sorted and de-duplicated, and omits an empty set. It percent-encodes a space as `%20` with upper-case hex, never `+`. A non-canonical URL shows its view and is replaced by the canonical form. *Test:* the same view reached by any path yields byte-identical URLs.
3. **SAF-URL-3 Navigation pushes history and refinement replaces it.** Moving to a different screen or entity pushes a history entry (Limen `Navigation.navigate`, `navigate`). Refining the current view replaces the entry (`Navigation.refine`, `refine`), so Back leaves the view rather than undoing each keystroke. Refining means search, sort, filter, tab, page or period. Adopting a URL on load or on Back/Forward never pushes (`Navigation.adopt`). Back, Forward and reload each restore the state from the URL alone. *Test:* a scripted session of navigate, refine, Back, Forward and reload, asserting the URL and the view at each step.
4. **SAF-URL-4 An unknown, deleted or unauthorized ID shows a clear state with a way back.** A URL that names an entity that does not exist, was deleted, or that the viewer may not see shows a not-found or not-permitted state. That state names what was requested without disclosing what the viewer may not see, and offers a way back to the parent view or home. A malformed parameter is a typed invalid outcome, never an exception: the application shows an invalid-link state or falls back to the default and canonicalizes. It never shows a blank page and never shows a different record. *Test:* each entity route opened with an unknown, a deleted and, where permissions exist, a forbidden ID.
5. **SAF-URL-5 URLs never carry secrets or sensitive data.** URLs end up in history, server and proxy logs, the `Referer` header, analytics, screenshots and chat. Tokens, credentials, session identifiers and API keys never appear in a path, query or fragment. Neither does sensitive personal or financial data: names, e-mail addresses, government or tax IDs, account or card numbers, or free text a person typed about someone. Entities are addressed by identifiers that carry no such data. These parameter names are refused, compared case-insensitively with `-` and `_` removed, exactly as Limen's route table refuses them (LCP-109): `token`, `access_token`, `id_token`, `refresh_token`, `password`, `passwd`, `secret`, `client_secret`, `api_key`, `key`, `session`, `session_id`, `auth`, `authorization`, `code`, `credential`, `credentials`. Query parameters an OAuth redirect leaves in the document are removed by a replace once consumed. Transient UI state does not go in the URL: open menus, hover, focus, unsaved form input, drafts and scroll position. *Test:* the verifier refuses a reserved name in the inventory, and a review of each route confirms its parameters carry no sensitive data.
6. **SAF-URL-6 Deep links work on static hosting.** A statically hosted application (GitHub Pages: relative URLs, no `<base href>`) uses **hash mode**: the route and its query follow `#/`, as in `index.html#/invoices/42?tab=history`. A reload or a pasted deep link then always fetches the same `index.html`, so it never 404s, and relative links resolve unchanged at every depth. A `404.html` fallback is not used: GitHub Pages answers such deep links with HTTP 404, and the fallback needs the base path. The decision is Limen's `DF-LIMEN-2026-0006`, which this standard adopts. `path` mode is only for hosts that answer every path with the application, such as server-rendered applications. *Test:* on the deployed site, reload each inventory route and paste it into a new browser. Each returns 200 and the same view.
7. **SAF-URL-7 Old links keep working.** When a route is renamed, moved or restructured, the old pattern stays as a legacy entry that redirects, by a replace, to the current route with its parameters carried over. A route is removed only with a legacy entry to its nearest surviving view. *Test:* every legacy entry, opened, lands on its target with parameters intact.
8. **SAF-URL-8 Every application publishes a route inventory.** The inventory is `.echelon/routes.json` with schema `echelon.routes/v1`. Limen's `Inventory.render` / `renderRouteInventory` writes it deterministically: sorted keys, two-space indent and a final newline. Limen publishes its schema as `contract/routes.schema.json`, and Praxis mirrors it as [`schemas/echelon-routes-v1.schema.json`](../schemas/echelon-routes-v1.schema.json). The inventory records the mode, the home, sign-in and not-found routes, and every route: its full name, pattern, parameters (name, `in`, type, required, default, values), guard, `requires` and whether it may be a return target. It also records the legacy entries. An application without Limen writes the same document. A route the application serves that the inventory omits is a defect. *Test:* `praxis foundations verify` (ECHELON-FND-ROUTING-001/002/004), plus a test that regenerates the inventory from the route table and compares it byte for byte.
9. **SAF-URL-9 Routes are parsed and formatted by pure, round-trip-tested functions.** The route table is an immutable value that is validated when defined (`RouteTable.define`, `defineRoutes`). One pure codec owns the mapping (`RouteCodec.create`/`parse`/`format`, `createRouteCodec`). It does no I/O and touches no browser globals. For every route and every generated parameter set, `format (parse url) = canonical url` and `parse (format route) = route`, property-tested in CI. Malformed input parses to a typed failure, never an exception. An application on Limen 0.9.0 or later uses Limen's routing module rather than a local router (ECHELON-FND-ROUTING-003). On an earlier Limen, including while 0.9.0 is unpublished, the check is pending (ECHELON-FND-ROUTING-005), never passed or failed. *Test:* the property tests run in CI.
10. **SAF-URL-10 Sharing is one action away where it is natural.** Views that people discuss or hand off, such as entity detail, filtered lists, reports and dashboards, offer a "Copy link" action that copies the canonical URL (Limen `Link.share`, `shareLink`). The action confirms the copy accessibly and works by keyboard. *Test:* activate Copy link, paste into a fresh context, and land on the same view.

## Dependency discipline and completion

Shared dependencies MUST use released versions or immutable artifacts. A missing shared capability MUST be recorded in the owning shared repository rather than silently reimplemented in Praxis.

A feature using an applicable shared capability is complete only when evidence shows the dependency is actually used and the relevant Aegis boundary, Forma browser/accessibility, or Folio print/PDF behavior is tested.
